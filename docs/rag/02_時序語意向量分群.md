# 02 - 時序感知語意向量分群（Temporal Vector Clustering）

## 1. 為什麼需要時序向量分群？

長對話往往跨越多個 40 則 Batch，導致同一件事在相同日期或連續時間內產出數條高度重疊的事件條目：
- `[2026-08-15] 兩人討論想去沖繩玩`
- `[2026-08-15] 兩人規劃沖繩行程想吃石垣牛`
- `[2026-08-15] 提到去沖繩租車的事`

若直接送入 Chroma，這 3 條向量彼此高度相似，使用者搜尋「沖繩」時 Top-K 會全被同天同一件事佔據。
然而，**若直接把同一天所有事件不加思索全丟給 LLM 判斷，會大幅消耗寶貴的 15 RPM 額度**。

**最佳解：先用 Embedding 計算語意相似度，篩出候選群組，再交由 LLM 處理。**

---

## 2. 演算法運作機制

```
所有候選事件條目 (N 條)
        │
        ▼ 批次呼叫 Gemini Embedding API (1 次 HTTP 請求，1500 RPM 配額)
取得所有事件的 768 維度向量
        │
        ▼ 本地雙重條件過濾（兩兩比對）
條件一：時間差 <= 36 小時（避免跨月份類似話題被錯誤關聯）
條件二：Cosine Similarity >= 0.80（語意強相關）
        │
        ▼ 圖論分群（Connected Components）
   ┌────┴──────────────────────────┐
孤立事件（無高相似對象）       高相似候選群 (Cluster 大小 >= 2)
   │                               │
   ▼                               ▼
直接保留（0 次 LLM 呼叫）      進入 03_lossless_consolidation 進行 LLM 仲裁
```

---

## 3. 核心參數與閥值依據

1. **時間差上限 (`EVENT_CLUSTER_MAX_HOURS_GAP = 36.0`)**：
   - 容納同日對話以及跨越午夜（23:30 ~ 01:00）的連續話題。
   - 拒絕將數週前與數週後的同名話題粗暴合併。
2. **語意相似度門檻 (`EVENT_CLUSTER_SIMILARITY_THRESHOLD = 0.80`)**：
   - **$\ge 0.88$**：近義重複，肯定同質。
   - **$0.78 \sim 0.85$（黃金區間）**：同一事件的不同側面或細節補充（如「沖繩旅遊」與「吃石垣牛與租車」）。
   - **$< 0.75$**：不同話題（如「沖繩自由行」與「去陽明山看夜景」），直接判定異質獨立，不呼叫 LLM。

---

## 4. 效能優勢
- **極速本地運算**：N 條事件的兩兩餘弦相似度在 NumPy 矩陣下僅耗時 1~3 毫秒。
- **節省 80%+ LLM 請求**：絕大多數日常事件彼此獨立，直接放行，將 15 RPM 額度保留給真正的重複群組。
