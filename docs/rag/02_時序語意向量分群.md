# 02 - 時序感知語意向量分群（Temporal Vector Clustering）

## 1. 核心定位與演算法革新

長對話在批次事件提煉後，同一事件往往在相近時間內產出多筆片段。
若不經篩選直接送入 LLM 融合，會大幅浪費 API 額度；若直接存入向量庫，檢索時 Top-K 會全被同天同主題佔滿。

系統在進入 LLM 融合前，先以**本地向量運算**進行時序感知分群：

- **演算法選型**：採用 **Complete Linkage（全連結 / 團分群）**。
- **徹底廢除 Single Linkage（連通元件）**：連通元件只要 $A \sim B$ 且 $B \sim C$ 就會強行合併，在對話語料中會產生嚴重的**鏈狀串聯效應（Chaining Effect）**，曾把 86 條不相干事件（看電影、看星星、吃臭豆腐、全聯預算）滾雪球串成單一巨型偽群組。
- **Complete Linkage 核心規則**：新事件若欲加入既有群組，必須與群組內「**所有既有成員兩兩之間**」均滿足門檻條件，徹底阻斷鏈狀串聯。

---

## 2. 演算法運作機制

```
所有候選事件條目 (N 條)
        │
        ▼ 取得 768 維度 Embedding 向量（優先取自本地快取）
兩兩時序與語意嚴格檢驗
        │
        ├─ 條件一：時間差 <= 24.0 小時（聚焦連續話題，阻斷跨日干擾）
        ├─ 條件二：Cosine Similarity >= 0.90（全成員兩兩均需滿足）
        └─ 條件三：單群容量上限 <= 4 條（避免過度堆疊稀釋細節）
        │
        ▼ Complete Linkage 團劃分
   ┌────┴──────────────────────────┐
孤立事件（不符全連結條件）       高同質小群 (Cluster 大小 2~4 條)
   │                               │
   ▼                               ▼
直接保留（0 次 LLM 呼叫）       進入 03_同質無損融合去重 進行 LLM 精煉
```

---

## 3. 核心參數與決策原因

1. **語意相似度門檻 (`EVENT_CLUSTER_SIMILARITY_THRESHOLD = 0.90`)**：
   - **實測經驗**：在 `gemini-embedding-2` 空間中，中文對話在 $0.80 \sim 0.85$ 處僅為詞彙（如「對方」、「去吃」）或句式相似，語意並非同事件。
   - **定於 0.90 之原因**：只允許**人事物高度專一且細節緊密重疊**的條目進入融合，其餘一律拆回獨立事件保留，兼具精準度與省額度。
2. **時間差上限 (`EVENT_CLUSTER_MAX_HOURS_GAP = 24.0`)**：
   - 容納同日對話與跨午夜話題延續，避免跨多天事件被過度歸納。
3. **單群上限 (`EVENT_MAX_CLUSTER_SIZE = 4`)**：
   - 限制每群最多 4 條，避免塞給 LLM 過長 Context 造成細節遺失。
